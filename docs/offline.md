# Installable app and offline use

Bauplan is a Progressive Web App (PWA). On a supported browser, use **Install app** or **Add to Home Screen** in the browser menu. On iPhone or iPad, open the site in Safari, choose **Share**, then **Add to Home Screen**. The app must be served over HTTPS, except when testing on localhost.

On Android and other browsers that support Web App Manifest shortcuts, long-press the installed app icon to open a new appointment, create a task, scan a receipt, or record an expense. iOS home-screen web apps may not expose these shortcuts.

## Receiving documents from other apps

On supported Android/Chromium systems, install Bauplan as a PWA, then share a PDF or image from a scanner, files, or photos app and select **Bauplan**. Choose **Quote**, **Invoice (open)**, **Expense / receipt (paid)**, or **General document**. Multiple files are processed one at a time. Quotes and expenses open the same import forms as manual entry, upload the file, and run OCR to prefill fields for review. OCR must be enabled and configured in the existing administration settings; if it is unavailable or disabled, the file remains linked and an explicit message asks for manual entry. Invoices are expenses, optionally linked to an existing quote; they do not create a second offer. General documents use the existing upload and recognition/assignment dialog.

Receiving requires HTTPS (or localhost), an installed PWA, and an active service worker. It is not supported by Safari/iOS, even for home-screen apps; use the in-app file picker there. After deployment, open the app online to update its service worker and manifest; some browsers require reinstalling the PWA before it appears as a share target. Development mode does not register a service worker.

Shared files are temporarily held in a separate, browser-profile-local Cache Storage inbox, not sent to the server by the share handler. The inbox survives login, setup, and reloads; processing starts only after an approved account has signed in and a project is available. It is not account-scoped: use a private browser profile, especially when sharing before login. **Later** keeps files pending; **Discard file** removes a file. Pending files expire after 24 hours (cleaned on the next share or inbox read), and the entire inbox is limited to 100 MB. Successful imports remove the temporary copy. Clearing site data removes pending shares. Offline receipt and quote uploads can be queued using the existing offline workflow, but OCR requires a server connection.

## Push notifications

Enable push per device in **Settings → Personal → Push notifications**. The server automatically uses the admin account's email address as its Web Push contact; no extra configuration is required. Task assignments and reminders are generated by the running server even when the PWA is closed. An offline assignment triggers push only after successful synchronization. Browser/OS permission, network access and a supported push provider are required; iPhone/iPad requires an installed Home Screen app on iOS/iPadOS 16.4 or newer. Push is not a silent background-sync mechanism. See [operations](operations.md#push-notifications) for reminder rules, delivery limits and setup.

## Before going offline

Offline creates, edits, deletions, and uploads complete after being saved to the local queue. Save dialogs close normally and a success toast explains that the change will synchronize automatically when the connection returns. If local persistence fails, saving fails visibly instead; the form remains open and no queued-success message is shown.

1. Open Bauplan while online and sign in on the browser profile and device you will use offline.
2. Allow the service worker to finish installing, then open the project once so its workspace snapshot is saved.
3. Reopen the app online after updates so the latest static app shell is installed.

The app shell and versioned static assets are cached. Authenticated API responses, private file URLs, and other server responses are not cached by the service worker. Workspace data and queued file uploads are stored locally in account-scoped IndexedDB. Previously uploaded document contents, OCR, and server-backed account or administration settings require a connection.

The document scanner's image-processing worker (about 16 MB) is not precached; it is cached the first time the scanner is used online. Scanning offline works only after that.

The PDF reader's worker and supporting fonts, character maps, and image decoders are hosted locally and cached as used, rather than all being precached at installation. Previewing a PDF still requires access to the document itself; authenticated document responses are not cached for offline use. The full-screen preview fills the app viewport on iOS without requiring native browser fullscreen support.

The scanner's local edge detection and optional automatic capture work without a server connection once its assets are available. Automatic capture starts off and always opens the crop/review step, not a save operation. Detection pauses while processing, when the page is hidden, and when leaving the scanner. Camera readiness and browser capabilities are checked at runtime; on iPhone, the home-screen PWA still uses WebKit's camera APIs, not Apple's native document-scanning APIs.

### Checking scanner improvements

Compare the same pages, lighting, distance, and device orientation before and after an update, with warmed scanner assets. Include both light/dark desks, shadows, skewed pages, text detail, and a scene without a document. Check preview smoothness, outline jitter, manual capture responsiveness, false automatic captures, and the saved PDF's legibility separately. Desktop emulation cannot certify iPhone camera performance.

For development, `SCAN_BENCHMARK=1 npm test -- src/lib/doc-scan/cv-ops.test.ts --reporter=verbose --silent=false` reports deterministic synthetic detection latency and corner error. In a development browser console, `(await import('/src/lib/doc-scan/live.ts')).readScanTimings()` returns at most 120 recent image-free samples: main-thread readback time, worker round-trip time, observation age, analysis size, and presented-frame count differences between sampled frames. Those count differences include intentionally skipped frames and are **not** a dropped-camera-frame measurement. Samples remain in memory only, are not collected in production, and are not sent anywhere. Use actual device measurements before asserting a performance percentage or native-scanner parity.

## Updates

After a new version is deployed, the app checks for it whenever it returns to the foreground and every 30 minutes. The new service worker activates immediately, but the page does not automatically reload, even in the background. An update icon appears in the header to the left of the connection status; save open forms before tapping it to load the new version. If a page from the old version can no longer load its code, the app reloads once automatically instead of showing an error. The current version is shown at the bottom of the sidebar, and on phones via the info icon in the header.

Open entry forms retain their current values when backgrounding the app and returning triggers a data refresh. Initial values are applied only when a dialog opens; closing and reopening starts a fresh form. These unsaved drafts remain in memory, not persistent storage: an OS-initiated page eviction, manual reload, or closing the app can still discard them.

The service worker is generated by `npm run build` and is not registered under `npm run dev`. To test installation or offline use locally, run `npm run build` and `npm run preview`.

## Offline behavior

While offline, the previously cached workspace can be viewed and edited. Creates, edits, and deletes are written to the local workspace and queued for replay. Document uploads are queued with their file data. The header shows offline and pending-sync status only when applicable; normal online operation has no connection indicator. Queued changes synchronize when a connection returns or when **Sync changes now** is selected.

The server checks each queued change against the exact row the device originally edited. If another device or user changed that row first, Bauplan keeps both versions and pauses that change for a decision:

- **Use server version** discards the queued local change.
- **Keep offline changes** rebases the local version on the current server row and retries it.

Resolve conflicts before signing out or changing accounts, or explicitly confirm discarding the pending work. Successful sign-out clears this account's local snapshot and queue.

Offline access is available only after the account has been used on that browser profile. A browser cannot verify whether a server-side session was revoked while the device was disconnected; offline access is therefore device/profile scoped, not a fresh authentication check. Local browser storage is not encrypted and should not be used on a shared browser profile. Clearing browser site data also removes the offline workspace and any unsynchronized changes.
